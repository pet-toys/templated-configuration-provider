10.3.0
======

Added:
- Inline default values for placeholders. Set
  TemplatedConfigurationOptions.DefaultValueSeparator (conventionally ":-") to
  let a placeholder carry its own fallback: {Db:Host:-localhost} resolves to
  the value of Db:Host when that key has one, and to the literal "localhost"
  when it does not. The first occurrence of the separator splits the
  placeholder, so a default may itself contain the separator. A default is
  literal text: an empty default erases the placeholder, and delimiters inside
  a default are not resolved further. The default is also used when the key
  resolves to an empty value, whereas a placeholder without a default still
  substitutes the empty string. A placeholder carrying a default always
  resolves, so its value is emitted by the provider and it never trips
  ThrowOnUnresolvedPlaceholders. The separator is unset by default, which
  leaves placeholder parsing exactly as it was.

10.2.4

  release pipeline no longer depends on a long-lived API key.

--------------------------------------------------------------------------------

10.2.3
======

Fixed:
- Placeholder resolution now reads only the configuration sources registered
  before AddTemplatedConfiguration(). Previously the provider also resolved
  against sources added after it (for example command-line arguments), so a
  later source could silently feed a placeholder even though it is meant to win
  over the templated result rather than supply it. Such a source no longer
  satisfies a placeholder; the value is left verbatim. The documented "register
  it after the sources it reads" arrangement is unaffected.

--------------------------------------------------------------------------------

10.2.2
======

Added:
- Opt-in strict mode for unresolved placeholders. Set
  TemplatedConfigurationOptions.ThrowOnUnresolvedPlaceholders to true to fail
  fast when a balanced placeholder cannot be resolved: the initial load throws
  InvalidOperationException naming the configuration key and the unresolved
  placeholder. The default remains lenient pass-through, and an unbalanced
  delimiter is always left unchanged. On a later reload an unresolved
  placeholder does not throw; the provider keeps the previous values and does
  not signal a reload.

10.2.0
======

Fixed:
- Reload now reflects the current state of the underlying sources: placeholders
  that have become resolvable are added, and keys that no longer resolve are
  removed. Previously these changes were missed on reload.
- A reload is signaled only when a resolved value actually changes, so
  IOptionsMonitor consumers are no longer notified for no-op reloads.
- Reloading a source now drops keys that were removed from it instead of
  keeping their stale values.
- Resources are now released in the correct order when the provider is disposed.

Changed:
- AddTemplatedConfiguration now validates the configured template delimiters and
  throws ArgumentException when the start and end characters are equal, match the
  configuration key delimiter (':'), or are whitespace or control characters.
